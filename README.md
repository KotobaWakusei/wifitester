# WiFiTester — 无线诊断工作台

WiFiTester 是面向已取得 Root 权限的 Android 设备的 **无线诊断与安全测试工作台**。不同手机、厂商固件和无线驱动的能力存在差异；APK 构建成功并不代表某台手机一定支持 Monitor（监听）模式。

> ⚠️ **重要免责声明**
> 本项目 **仅供合法的无线网络诊断、课程实验和经授权的安全测试**。
> - 使用者必须拥有目标网络/设备，或事先取得网络所有者明确、可验证的书面授权。
> - 必须遵守所在地法律、无线电监管要求及组织政策。
> - 本软件 **提供** 无线注入、强制断开客户端、口令验证、伪接入点、ARP 欺骗等主动测试功能，因使用这些功能而触犯任何规则，属个人行为，与本项目无关。
> - 监听模式、切换频道或关闭接口可能中断本机网络连接；抓包可能收集第三方通信元数据。请优先使用隔离实验网络，遵循数据最小化原则，并妥善保护日志与抓包文件。

## 界面结构

应用采用 **三个主界面 + 底部导航栏** 的结构，标签页之间保持存活，切换不会丢失扫描结果与工具状态。

| 标签 | 内容 |
| --- | --- |
| **Wi-Fi** | 当前连接状态与附近网络列表。列表显示 SSID、BSSID、信号强度、频段、频道、安全类型与信号等级，可按信号 / 频道 / 安全类型排序，可隐藏弱信号网络，可固定常用网络。 |
| **工具** | 全部工作台入口，分为「只读诊断」（监听抓包、抓包分析、断开帧分析、网络清单、工具链清单）与「主动测试」（攻击工作台）两组。 |
| **设置** | 外观（主题与界面语言）、抓包默认值、Root 检测与授权、主动功能授权开关、口令字典路径、保持屏幕常亮、版本信息。 |

底部导航使用 Material 3 `BottomNavigationView`，带活动指示器与无障碍标签；三个标签页用 show/hide 保持存活，切换不会丢失扫描结果与工具状态。

### 外观与语言

- **主题**：Material 3 `Theme.Material3.DayNight`，默认 **跟随系统** 的深浅色设置；也可以在「设置 → 外观 → 主题」中强制浅色或深色，选择会被记住并立即生效（`AppCompatDelegate.setDefaultNightMode`）。
- **界面语言**：默认 **跟随系统** 语言；也可以在「设置 → 外观 → 界面语言」中固定为简体中文或 English。Android 13 及以上同时支持系统「应用语言」设置（`res/xml/locales_config.xml`）。
- 全部文案都来自 `res/values/strings.xml` 与 `res/values-en/strings.xml`；代码中不再保留硬编码的中文串。`TranslationCoverageTest` 会校验两份词条一一对应且占位符一致，缺失翻译会让 CI 失败。

**二级菜单（网络详情）**：在 Wi-Fi 标签中点按任意网络即可打开 `NetworkDetailActivity`，其中给出完整的无线参数（SSID、BSSID、RSSI、频率、频道、频段、安全类型、是否企业认证、能力信息、最后出现时间），并提供常用操作：

- 连接 / 切换到此网络（跳转系统 Wi-Fi 面板）
- 复制 SSID、复制 BSSID
- 分享网络信息（只读文本报告）
- 固定 / 取消固定到列表顶部
- 在监听工作台中分析（自动带入频道）
- 在攻击工作台中选定（自动带入 BSSID 与频道）
- 忘记此网络（仅支持当前已连接网络的凭据；其他网络需在系统设置中处理）

## 功能

- **Root 权限检测**：通过执行 `su -c id` 并验证返回结果是否为 UID 0，判断是否真正获得 Root；检测包含超时，避免授权弹窗未处理时界面永久卡住。
- **可扩展监听后端**：界面通过 `MonitorModeBackend` 调用标准 Linux `iw/ip` 后端；后续可以在不重写界面的前提下添加厂商/驱动适配。能力探测与命令执行结果分开判断，不会将工具存在误报成驱动支持。
- **状态感知的恢复流程**：记录接口原始 UP/DOWN 状态；不会删除本应用未创建的监听接口，并在停止或启动失败时尽力恢复原状态。
- **诊断报告导出**：将当前诊断日志保存为用户指定的文本文件。
- **只读 Wi-Fi 网络清单**：通过 Android 公共 Wi-Fi 扫描 API 展示可见 SSID、BSSID、信号强度、频率/频道及系统报告的安全能力，并支持分享文本报告。
- **内置工具链基础设施**：APK 可携带按 ABI 区分的命令行工具，首次启动时释放到应用私有目录，并配置专用 `PATH` 与 `LD_LIBRARY_PATH`。CI 构建并打包 Android ARM64 的 `tcpdump`（静态链接 libpcap）、`aircrack-ng` 套件（`aircrack-ng` / `airodump-ng` / `aireplay-ng` / `airmon-ng`）、`hostapd` 与 `arpspoof`；缺失项会明确显示，不会假装已内置。
- **Aircrack-ng 工具清单**：分别检测 `aircrack-ng`、`airodump-ng`、`aireplay-ng`、`airmon-ng`、`tcpdump`、`iw`、`ip`、`capinfos`、`tshark`、`hostapd`、`arpspoof` 是否可执行，并标出工具路径与来源；工具可用不等于驱动支持监听模式。
- **aircrack-ng 图形工作台**：提供工具可用性检测、版本/帮助信息查看、被动抓包文件只读分析。
- **有限 PCAP 抓包与导出**：监听工作台将被动抓包写入应用私有目录，单次上限为 50,000 帧、每帧快照 512 字节；停止后可导出标准 PCAP 文件供 Wireshark 等工具继续分析。
- **抓包文件只读分析**：导入前检查 PCAP/PCAPNG 文件头，拒绝未知格式；单文件读取上限 200 MiB，优先使用 `capinfos` 或 `tshark`，否则通过 `tcpdump -r` 读取有限的数据包摘要；可导出分析报告。
- **主动测试工作台**：在明确授权后可执行断连洪水、信标洪水、认证洪水、握手捕获、离线口令验证、伪接入点与 ARP 欺骗，详见下节。
- **Material 3 界面**：基于 AppCompat + Material Components 1.11 构建。卡片、按钮、开关、文本框、芯片、分隔线与底部导航均使用官方组件；所有颜色来自主题角色（`colorPrimary` / `colorSurface` / `colorOnSurfaceVariant` …），浅色与深色方案由 `values/colors.xml` 与 `values-night/colors.xml` 分别定义，因此切换主题时不需要重建界面。
- **统一的日志面板**：所有工作台的输出都使用同一套终端样式面板 —— 等宽字体、圆角背景、行距、行数计数器与清空/导出操作。
- **中英文界面**：三个主界面、网络详情页与全部工作台的文案全部来自资源文件，并提供英文翻译；代码中不存在硬编码的中文界面文案。

## 主动测试工作台

「工具 → 攻击工作台」提供下列模块。每个模块都标注了风险等级，并在启动前弹出确认对话框，明确列出目标、工具与将要执行的命令。

| 模块 | 风险 | 需要的工具 | 说明 |
| --- | --- | --- | --- |
| 断连洪水 | 干扰性发送 | `aireplay-ng` | 向目标 BSSID 发送 deauthentication / disassociation 帧，可指定单个客户端 |
| 信标洪水 | 干扰性发送 | `aireplay-ng` | 持续广播伪造 beacon 帧 |
| 认证洪水 | 干扰性发送 | `aireplay-ng` | 发送伪造认证请求，占满接入点连接表 |
| 握手捕获 | 被动接收 | `airodump-ng` | 监听目标接入点并保存 WPA/WPA2 四次握手 |
| 离线口令验证 | 离线计算 | `aircrack-ng` | 用字典比对已捕获的握手，**不产生任何射频活动** |
| 伪接入点 | 身份仿冒 | `hostapd` | 广播与目标同名的接入点，评估客户端的接入点选择行为 |
| ARP 欺骗 / 中间人 | 身份仿冒 | `arpspoof` | 对指定客户端实施 ARP 欺骗，配合流量转发实现中间人观测 |

**安全护栏**：

1. 必须在「设置 → 安全与授权」中显式确认已获得网络所有者授权，未确认时所有主动模块的启动按钮保持禁用。
2. 每个模块启动前都要通过确认对话框，对话框中显示目标 BSSID、工具名与完整命令。
3. 所有注入类模块都要求设备上已存在监听接口（由监听工作台创建），避免在托管模式下误发帧。
4. 目标 BSSID、客户端 MAC、接口名、路径与 SSID 在拼装命令前都经过严格校验（MAC 格式、接口名字符集、绝对路径、SSID 长度与控制字符），防止把非法输入带进 shell。
5. 执行日志可随时导出，便于留存审计记录。

## 系统要求

- Android 5.0（API 21）或更高版本；较新的 Android 版本和厂商系统可能施加额外限制。
- 通过 Root 管理器授予本应用 Root 权限。
- 当前构建流程将 Android ARM64 版 `tcpdump`、`aircrack-ng` 套件、`hostapd` 与 `arpspoof` 内置于 APK；监听模式仍需要可用的 `iw` 和 `ip`，并要求驱动支持 Monitor 虚拟接口与目标频道。不能将“工具内置”视为“驱动支持”。
- Wi-Fi 扫描需要 Android 定位权限；部分设备还要求打开系统定位开关，并可能受到扫描频率限制。
- 主动测试模块还需要目标网络所属芯片组的驱动允许原始帧注入；多数手机默认不允许。

## 构建

项目使用 Gradle 8.7、JDK 17 和 Android SDK Platform 34。界面层依赖 `androidx.appcompat:appcompat:1.6.1` 与 `com.google.android.material:material:1.11.0`。

```bash
gradle --no-daemon assembleDebug
```

APK 输出路径为 `app/build/outputs/apk/debug/app-debug.apk`。GitHub Actions 会在推送、Pull Request 和手动触发时运行单元测试并构建调试版 APK；请在对应工作流运行记录中下载 `wifitester-debug-apk` 构建产物。

### 构建内置工具链

```bash
export ANDROID_NDK_HOME=/path/to/android-ndk
bash tools/build-android-toolchain.sh
```

脚本会依次构建静态 libpcap、`tcpdump`、OpenSSL、`aircrack-ng` 套件、`hostapd` 与 `arpspoof`，产物写入 `app/src/main/assets/toolchain/arm64-v8a/`。

- `arpspoof` 由仓库内的 `tools/native/arpspoof.c` 编译，不依赖任何外部镜像，因此结果可复现。
- 每个下载源都配有备用镜像；单个可选步骤失败只会给出警告并跳过对应功能。
- 设置 `WIFITESTER_STRICT_TOOLCHAIN=1` 可把警告转为硬错误。
- 宿主需要 `make`、`flex` 与 `bison`（Debian/Ubuntu：`sudo apt-get install -y build-essential flex bison`）。缺少时脚本会在开头给出明确提示。

内置二进制属于构建产物，已在 `.gitignore` 中排除，由 CI 重新构建。

## 使用监听模式

1. 打开 **WiFiTester 无线诊断**，按提示在 Root 管理器中授权。
2. 进入 **工具 → 被动监听与抓包**，点击 **重新检测设备**，刷新无线接口、工具和驱动公开的频道。
3. 选择接口与频道，仔细阅读可能导致 Wi-Fi 中断的提示，再启动监听。
4. 被动抓包保存在应用私有目录，采集限制为最多 50,000 帧、每帧快照 512 字节。
5. 完成后点击 **停止并恢复**，等待 PCAP 关闭，并确认普通 Wi-Fi 连接已恢复。
6. 点击 **导出最近的 PCAP 抓包**，再用 Wireshark 或其他只读工具分析；也可在 Aircrack-ng 工作台导入 PCAP/PCAPNG 并导出分析报告。
7. 排查问题时，使用 **导出完整诊断报告** 保存文本报告。

## 已知限制

- `iw list` 仅反映驱动公开声明的能力，不保证运行时一定能创建接口或切换频道。
- 部分厂商驱动不支持 Managed 与 Monitor 接口并发；启动监听可能中断当前 Wi-Fi。
- 绝大多数 Android 设备的 WLAN 驱动拒绝原始帧注入，即使监听接口创建成功，`aireplay-ng` 仍可能报 `Permission denied`。
- `hostapd` 需要驱动支持 AP 模式与多站（STA/AP 并发），在手机平台上通常无法真正广播伪接入点。
- Android/厂商策略、监管域、固件和 Root 管理器行为都可能影响结果。
- 清理与恢复流程尽力而为。如果设备未能自动恢复，请停止应用并在 Android 设置中恢复 Wi-Fi；不要仅凭命令返回成功就认定无线功能已完全恢复。
- 频道编号来自驱动或 Android 扫描 API 提供的频率信息，不代表所有地区都允许或支持使用对应频道。

## 故障排查

- **Root 不可用**：打开 Root 管理器确认已授权 WiFiTester，然后点击首页 Root 状态卡片或设置页的 **重新检查 Root**。
- **未发现接口或频道**：确认 Root 环境下的 `iw` 可以运行，并导出诊断报告查看详细输出。
- **监听启动失败**：检查命令输出。驱动可能拒绝创建 Monitor 接口、拒绝并发接口，或不支持所选频率。
- **攻击模块无法启动**：先在监听工作台创建监听接口，再确认 `aireplay-ng` / `hostapd` / `arpspoof` 已在设备上可用；多数手机驱动会直接拒绝注入。
- **Wi-Fi 未恢复**：在 Android 系统设置中关闭并重新打开 Wi-Fi，然后先收集诊断报告再重试。
- **扫描结果为空**：授予定位权限；如设备要求，请打开系统定位开关，并在 Android 扫描限流窗口过后重试。

## 后端架构

- `MonitorModeBackend` 定义设备/驱动适配契约，当前实现 `IwMonitorModeBackend`，通过标准 `iw`/`ip` 执行能力探测、监听接口创建、频道调谐和恢复。
- UI 不直接拼接厂商专用命令。后续新增 Qualcomm/厂商驱动适配时，应实现独立后端，并用测试验证能力探测、失败清理和恢复行为。
- `RootShell` 统一封装所有特权命令调用：所有执行都有超时上限，Root 弹窗未被处理时不会阻塞界面。
- `RootProcess` 管理长时间运行的注入进程，会回读真实 pid，以便停止时终止工具本体而不是外层 `su` 包装进程。
- `AttackCommandBuilder` 负责主动模块的命令拼装与输入校验，不依赖 Android API，因此可以完整地单元测试；校验失败时抛出携带资源标识的 `ValidationException`，由界面解析成当前语言的提示。
- `SettingsStore` 集中管理偏好项的键、默认值与合法性校验，避免 UI 与后台线程对同一限制产生分歧。
- `AppConfig` 集中管理外观偏好（主题模式、界面语言），`WiFiTesterApp` 在进程启动时把它们应用到 AppCompat 委托上。
- `UiKit` / `LightKit` 是全部界面的构建块：颜色一律通过主题属性解析（`Theme.color`），因此同一段代码在浅色与深色方案下都正确。
- `NetworkEntry`、`AttackCatalog`、`ToolCatalog` 只保存分类与资源标识，不含翻译文本，单元测试无需 Android 运行时。

## 开发与验证状态

CI 负责验证代码编译和 APK 打包，但不能替代真机测试。Root 授权、监听模式启动、频道切换、抓包输出、停止/恢复、报告导出，以及主动模块的注入行为，仍需在实际设备上验证。反馈问题时，请提供设备型号、Android 构建版本、驱动/工具输出和诊断报告（分享前先检查其中的隐私信息）。
